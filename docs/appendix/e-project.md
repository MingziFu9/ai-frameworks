# 附录 E 实验报告模板与综合项目指南

## E.1 实验报告模板 { #e1 }

每个实验的“实验报告要求”都按这个模板来写。报告不在长，**写清楚你做了什么、看到了什么、想明白了什么**就好。可以直接把下面的内容复制到 Word 或 Notebook 的文字单元格里填写。

```text
实验名称：实验 __-__  ______________________
姓名：________  学号：________  日期：________
版本：□ 通用版（Keras）  □ 国产版（飞桨）
环境：□ 魔搭  □ AI Studio  □ 本机    用的是：□ CPU  □ GPU

一、实验目的（照抄实验开头的“实验目的”即可）

二、我做了哪几档
    □ 第一档 · 跑通    □ 第二档 · 改一改    □ 第三档 · 挑战

三、关键结果
    （贴运行结果截图，或把实验记录表填好贴上来。
      数字要写清楚是训练集还是验证集。）

四、我改了什么，结果怎么变（第二、三档必填）
    | 改了什么 | 改之前 | 改之后 | 我的解释 |
    |---------|-------|-------|---------|

五、遇到的问题和解决办法
    （报错的最后一行是什么？查了哪里？怎么解决的？
      没遇到问题也可以写“哪一步最容易出错”。）

六、思考题回答

七、一句话总结：这个实验让我明白了 ______________
```

!!! tip "写报告的三个小窍门"
    1. **截图要有用**：截运行结果的最后几行就够了，不用截一整屏代码；
    2. **数字要成对**：写准确率时，同时写训练集和验证集，才能看出有没有过拟合（第 6 章）；
    3. **解释用自己的话**：“学习率太大，损失跳来跳去降不下去”比照抄定义更好。

### E.1.1 评分参考 { #e11 }

| 项目 | 分值 | 要点 |
|---|---|---|
| 完成度 | 40 | 第一档跑通得 30 分，完成第二档再加 10 分 |
| 结果记录 | 20 | 记录表完整，数字真实，截图清楚 |
| 分析 | 25 | 能解释结果为什么是这样；改参数后能说出变化的原因 |
| 问题与思考 | 15 | 如实记录遇到的问题；思考题回答合理 |
| 加分 | 最多 10 | 完成第三档挑战，或提出了书上没有的改进 |

**说明**：结果和书上不一样不扣分，书上的数字是编者电脑上的结果，换电脑、换版本有差别是正常的。如实记录比“凑”出和书上一样的数字更重要。

## E.2 综合项目进度安排 { #e2 }

综合项目对应[实验 12-2](../chapters/12-ecosystem/index.md#12-2)，选题和要求见 [12.6 节](../chapters/12-ecosystem/index.md#126)。建议 2～3 人一组，用 3 周课后时间完成。

| 时间 | 要做的事 | 交什么 | 参考章节 |
|---|---|---|---|
| 第 12 章课内 | 讨论选题，填项目计划表 | 项目计划表 | 12.6 |
| 第 1 周 | 收集数据、整理成文件夹、写数据说明 | 数据说明（数量、来源、许可、个人信息处理） | 第 3 章、12.4 |
| 第 2 周 | 训练、调参、评估、错误分析 | 实验记录表（至少 3 次尝试）、混淆矩阵 | 第 5–7、9、10 章 |
| 第 3 周 | 做成网页并发布、写报告和模型卡 | 网页链接或截图、项目报告 | 第 11 章、本附录 |
| 最后一次线下课 | 5 分钟展示，回答 2～3 个问题 | 展示 | — |

### E.2.1 每类项目的“最小可行版本” { #e21 }

时间紧的组，先做出下面的最小版本，再慢慢改进：

| 方向 | 最小版本 | 改进方向 |
|---|---|---|
| 图像 | 3 类、每类 50 张，用实验 7-1 的迁移学习代码，验证准确率超过 70% | 加数据增强、多拍不同光线和角度、试微调 |
| 文本 | 3 类、每类 100 条，用实验 9-2 的分类器 | 改句子长度、换 GlobalAveragePooling1D、和大模型 API 比一比 |
| 语音 | 4 个词、每个词 30 条，用实验 10-2 的代码 | 多找几位同学录音、加噪声、加 Dropout |

## E.3 项目报告模板 { #e3 }

```text
项目名称：______________________
组员和分工：______________________
网页链接（或截图）：______________________

一、需求
    1. 解决谁的什么问题？（例：帮食堂快速识别餐盘里的菜品）
    2. 这是分类、检测还是识别问题？要认哪几类？
    3. 有没有现成模型可以直接用？为什么还要自己训练？

二、数据
    1. 每类多少条？怎么收集的？
    2. 来源和许可（自己拍的写“自己拍摄”；用公开数据集的写名称、网址、许可）
    3. 有没有个人信息（人脸、声音、姓名、电话）？怎样处理的？（脱敏、征得同意、删除）
    4. 训练集和验证集怎么分的？

三、模型与训练
    1. 用的什么方法？（现成模型 / 迁移学习 / 从零训练 / 大模型 API）为什么？
    2. 主要设置：轮次、批大小、学习率、有没有数据增强、早停
    3. 实验记录表（至少 3 次改进尝试）
       | 日期 | 改了什么 | 训练 / 验证准确率 | 结论 |

四、评估与分析
    1. 最终的验证准确率
    2. 训练曲线截图，判断有没有过拟合
    3. 混淆矩阵：哪两类最容易混？
    4. 至少 3 个认错的例子，分析可能的原因

五、应用与发布
    1. 网页截图
    2. 发布在哪个平台？别人怎么用？

六、模型卡（见 E.4）

七、总结
    1. 做得好的地方
    2. 还没解决的问题，如果再给一周会怎么改
    3. 每位组员的收获（各一两句）
```

## E.4 模型卡模板 { #e4 }

[模型卡](../appendix/glossary.md#g-模型卡)像药品说明书，告诉使用者这个模型能做什么、不能做什么（[12.3 节](../chapters/12-ecosystem/index.md#123)）。下面左边是要写的项目，右边是用本书花卉识别器写的示例。

| 项目 | 要写什么 | 示例：花卉识别助手 |
|---|---|---|
| 模型名称和版本 | 名称、日期、谁做的 | 花卉识别助手 v1，2026-10，第 3 组 |
| 用途 | 能做什么 | 识别照片中的 5 种花：雏菊、蒲公英、玫瑰、向日葵、郁金香 |
| 不能用于 | 明确禁止或不适合的用途 | 不认识这 5 种以外的花，遇到别的花也会硬选一种；不能用来判断植物是否有毒、能否食用 |
| 方法 | 用的什么模型和框架 | 在 MobileNetV2（ImageNet 预训练）上做迁移学习，Keras 3 |
| 训练数据 | 来源、数量、许可 | TensorFlow 花卉数据集选取的 750 张，每类 150 张，CC BY 2.0 |
| 效果 | 在什么数据上、准确率多少 | 在 150 张验证集上准确率 82.7% |
| 容易出错的情况 | 错误分析的结论 | 玫瑰和郁金香容易混；花很小、光线暗、一张图里有多种花时容易认错 |
| 局限和风险 | 使用时要注意什么 | 训练照片多数是白天户外拍的，室内灯光下效果可能变差；结果仅供参考 |
| 隐私 | 是否收集用户数据 | 网页不保存用户上传的照片 |
| 联系方式 | 发现问题找谁 | 第 3 组，班级群 |

## E.5 综合项目评分表 { #e5 }

| 项目 | 分值 | 优秀（满分） | 合格（约 60%） |
|---|---|---|---|
| 需求与选题 | 10 | 问题清楚，有实际用处，难度合适 | 选题能做，但用处说得不太清楚 |
| 数据 | 20 | 数量达标，来源合法，处理了个人信息，写了数据说明 | 数量基本达标，来源写得不完整 |
| 模型与训练 | 20 | 方法合适，至少 3 次有记录的改进 | 跑通了训练，改进记录少于 3 次 |
| 评估与分析 | 20 | 有准确率、训练曲线、混淆矩阵，至少 3 个错例分析且原因合理 | 只有准确率，错误分析很少 |
| 应用与发布 | 20 | 网页能用、有链接，界面写明了能做和不能做的事 | 网页能在本机运行，没有发布 |
| 报告与展示 | 10 | 报告完整，模型卡清楚，展示时能回答问题 | 报告基本完整，回答问题有困难 |

!!! warning "这些情况要扣分"
    - 用了别人的数据却没写来源；
    - 录了同学的声音、拍了别人的脸，却没有征得同意；
    - 报告中的数字和代码运行结果对不上；
    - 网页上没有任何关于“模型可能出错”的提示。
